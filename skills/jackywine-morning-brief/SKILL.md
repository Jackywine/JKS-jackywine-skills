# jackywine 早报

可共享、可迭代的早报模板（JKS · jackywine skills）。例程只负责「何时醒、发给谁、数据从哪来、X 列表是哪一份、自己的 X 账号是谁、是否滴灌」；本 skill 负责「怎么读、怎么写、模块怎么拼」。

## 核心附加价值

早报的价值**不是**把用户昨天已记过的内容再念一遍。用户打开笔记工具就能看到原文；本 skill 要交付的是他**自己回看时不容易立刻得到**的东西：

1. **精选**：从昨日可报笔记里只挑最多 **3** 条真正值得今天再想一想的
2. **串库**：在笔记库里找出与这 3 条相关的旧笔记（同源主题、互补观点、前后演变），列出可点链接
3. **推荐理由**：用一两句说清「为什么是这三条、为什么要连着看那些旧笔记」——指向行动、选题、对照或纠偏，而不是复述原文
4. **视野外一瞥**：从用户指定的 X 设计列表（例：JAD）里，捞过去一周点赞最高的一条设计推文，**并把原帖设计图贴进消息**
5. **我的推**：日复盘自己昨天发的帖（1～2 条）+ 周一补周热（过去 7 天最高赞 1～3 条），各串库写启发——不是运营 KPI 报表
6. **优质列表日热**（例：JPI）：过去约 24h 列表最高赞 1 条；写与用户的关联、相关笔记、可选商业机会、逻辑漏洞或自媒体套路

改本 skill 或写同类 skill 时，先问：去掉「复述用户已有记录」之后，还剩什么？剩不下就别写那一段。

## 必要难度滴灌（可选，推荐）

若例程开启滴灌：

- 当天只把队列里的 **第 1 条**发给用户
- 用户回复有启发后再推下一条；无回复则停（视为未读，避免空烧）
- 队列顺序建议：精选笔记 → 设计周热 → 我的推 → 列表日热 →（可选）本地产出摘要

原理：一次塞整份会产生「都扫过了」的流畅错觉；一条一条强迫提取与生成，才把内容写进自己的语义网（desirable difficulty / testing effect）。哲学：**主动建构 > 被动投喂**；注意力是选票。

## 输出原则

- 大白话、观点鲜明；适合手机扫读
- 正文精选最多 **3** 条笔记；有命中才写：设计周热、我的推（周一可加周热）、列表日热
- **禁止**：罗列全部笔记、教练腔、口号收尾、假大空、硬套框架、大段复述原文、运营 KPI 说教
- 排版：总览 → 精选 → 设计周热 → 我的推 → 列表日热 →（可选）本地产出
- 能链尽链；找不到可靠链就如实说，不编链接
- 设计周热有命中必须附图（最多 4 张）
- 各模块全空 → 完全安静；只有一节有料也可只发那节

## 隐私：情绪类一律跳过

- 情绪、心情、焦虑、低落、心境、内心状态、动机挣扎等：**不报、不分析、不附链、不计入候选、不做关联**
- 拿不准就跳过；不要写「已跳过 N 条」

## 数据模块

| 模块 | 做什么 | 注意 |
|------|----------|------|
| A. 昨日笔记 | 只读昨日笔记，剔情绪类后精选 | 禁止写入/删除/改笔记 |
| A2. 相关旧笔记 | 对已挑中的每条在库内检索 | 宁可少链，不硬凑 |
| A3. 第二库（可选） | 如 Obsidian，仅可读且主题明确相关时附链 | 读不到就跳过 |
| B. 本地产出（可选） | 仅当本轮已有结果：干了啥、路径、一句结论 | 没结果就不提 |
| C. 精选引擎 | 决定哪 ≤3 条进早报 + 理由 | 见下 |
| D. 设计列表 · 周热 | 例程指定 List，过去 **7 天**最高赞 **1** 条 + 附图 | 只读；id 写在例程 |
| E. 我的推 | 例程指定账号；日复盘 1～2；周一周热 1～3 | 只读；情绪帖跳过 |
| F. 优质列表 · 日热 | 例程指定 List（例 JPI），过去约 **24h**最高赞 **1** 条 | 只读；机会/套路有才写 |

## 精选规则（最多 3 条）

1. 能直接服务正在推进的事
2. 和库里已有主题形成对照或升级
3. 可变成教程、推文、分享素材
4. 纯备忘/琐事默认不进

落选的不要附录列出。

## 模块 D · 设计周热

1. 分页读列表至早于「此刻往前 7 天」
2. 过去 7 天内按 `like_count` 取最高 1 条（并列取更新）
3. 写出：`@handle`、一句意、赞数、原帖链接
4. **附图必做**：最多 4 张；失败则保留文字并注明
5. 读不到 / 无帖 → 整节删

## 模块 E · 我的推

### E1 日复盘（每天）

1. 过去约 24h 公开原帖；丢纯 RT、情绪帖
2. 最多 1～2 条；空则整节删
3. 串库 + 启发（结构/坑/钩子）；不写 KPI 说教
4. 有图最多 2 张

### E2 周热（仅周一）

1. 过去 7 天自己原帖按赞取 1～3 条
2. 与日复盘去重：重叠只进周热

排在设计周热之后、列表日热之前。

## 模块 F · 优质列表日热（例：JPI）

1. 过去约 24h 列表帖按赞取最高 1 条；空则整节删
2. 写出：作者、赞、一句意、原帖链
3. **和你的关联**：对照用户主线；弱相关就老实说
4. **相关笔记**：1～3 条带链；无则省略
5. **商业机会**（可选）：仅能接到用户已在做/已公开的事时写；否则删段
6. **逻辑 / 套路**（可选）：论证跳跃、幸存者偏差、标题党等——有才写、写具体
7. 有图最多 2 张

排在我的推之后、可选本地产出之前。

## 推荐理由

每条笔记 2～4 句，至少碰到两类：为何推这条；为何连这些旧笔记；理论（仅当真支撑）；对外素材钩子。

洞察不得推测用户情绪。禁止口号收尾；禁止把用户没做过的事写成做过。

## 模块组合顺序

1. 昨日笔记 → 剔情绪 → 精选 ≤3 → 串库
2. 设计列表周热 → 附图
3. 我的推（周一加周热）
4. 优质列表日热 → 串库 + 关联/机会/套路
5. 可选本地产出
6. 组装发出；若滴灌则按队列每次只推 1 节

## 边界与安全

- 默认只读笔记库 / 可选第二库 / 例程指定的 X List 与自己账号；不对 X 写入（不发推、不点赞、不回复、不关注），不擅自改笔记
- 内容铁律：非用户亲身经历不写成他「做过」
- 附加价值优先于完整度

## 例程如何引用（示例）

> 运行本 skill。昨日笔记只读自取；相关旧笔记库内检索；设计周热用本例程写明的 List id 且必须附图；我的推用本例程写明的账号；列表日热用本例程写明的优质 List id 取过去约 24h 最高赞 1 条并串库；可选开启必要难度滴灌。各模块全空则安静。

具体时间、收件人、List id（设计列表 / 优质列表）、自己的 X handle、是否滴灌，写在**例程**里。
